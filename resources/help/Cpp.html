C/C++ - Plugin

Mit diesem Plugin können C/C++-Aufgaben erstellt, ausprobiert und automatisch mit Catch2 bewertet werden.

Beispiele

Im Tab UnitTest ein Beispiel auswählen und mit Apply laden. Die Beispiele zeigen Funktionstests, die Prüfung von stdout und das Lesen von number.txt. Die Templates müssen noch vervollständigt werden. Das Laden ersetzt Template, Tests und Dateiliste; bei vorhandenem Code oder Dateien erscheint eine Rückfrage.

Kurz erklärt

  • UnitTest: Enthält die Catch2-Tests, mit denen die eingereichte Lösung geprüft wird. Diese Tests werden als C++ kompiliert (Standard: C++17).
  • Template: Code, der den Studierenden als Angabe vorgegeben wird.
  • Files: Zusätzliche Dateien hochladen, herunterladen oder aus der Aufgabe entfernen.
  • Configuration: Sprache der Antwort, CPU-Limit und verfügbare Studentenbuttons festlegen.

Buttons

  • Format: Formatiert den aktiven Code-Editor mit clang-format und speichert das Ergebnis. Die Änderung lässt sich im Ace-Editor rückgängig machen. Studierende verwenden Format Code.
  • run: Kompiliert das Template und führt dessen main-Funktion aus. Nur im Tab Template verfügbar.
  • compile: Prüft das Template mit C17 oder C++17; Warnungen werden als Fehler behandelt. Nur im Tab Template verfügbar. Der Code wird weder gelinkt noch ausgeführt. Funktionstests benötigen hier keine main-Funktion. Compilerdiagnosen erscheinen im Ausgabefeld.
  • check: Führt die Catch2-Tests mit dem Template-Code aus und zeigt das Prüfergebnis an.
  • score: Berechnet die Punkte aus den Catch2-Testfällen. Jeder TEST_CASE zählt als ein bewerteter Fall; einzelne Assertions erhalten keine eigenen Punkte. Ein Kompilierungsfehler ergibt null Punkte.

Erfolgreiches compile prüft weder ungelöste Referenzen noch die Catch2-Tests. Dafür check oder score verwenden. Das gemeinsame Ausgabefeld und die Hilfe lassen sich ein- und ausblenden; der Trenner zwischen Editor und Ausgabe lässt sich verschieben.

Configuration

Die Tabs Compiler und clang-format enthalten die Code-Einstellungen. Daneben zeigt Available dataset variables die aktuellen Namen, Werte und Einheiten. Die Verwendung im Lehrertest ist im Abschnitt Dataset variables (teacher tests) beschrieben.

  • Answer language: C17 oder C++17 für Template und Studentenlösung auswählen.
  • enable run: Zeigt den Button Run Code in der Aufgabe an.
  • enable compile: Zeigt den Button Compile Code in der Aufgabe an.
  • CPU time limit (seconds): Begrenzt die Prozessorzeit (Standard: 5 Sekunden).
  • clang-format configuration (YAML): Im Tab clang-format die Formatierungsoptionen dieser Aufgabe eintragen, z. B. BasedOnStyle: LLVM und IndentWidth: 4. Eine leere Konfiguration verwendet die Vorgaben. Die Einstellungen werden mit der Aufgabe gespeichert und von den Format-Buttons für Lehrende und Studierende verwendet; sie gelten für Lehrertests, Template und Studentenlösung.
  • Additional compiler flags: Im Tab Compiler zusätzliche Optionen für run, compile, check und Bewertung eintragen, durch Leerzeichen oder Zeilenumbrüche getrennt, z. B. -O2 -Wextra -DNUMBER=42. -std=c++20 ändert den C++-Standard; Die Vorgaben sind C17/C++17 und -Wall -Werror; -Wno-error erlaubt Warnungen. C-Standardoptionen ändern den C++17-Teststandard nicht.

C/C++ programming questions

Studentenlösung und Lehrertests werden getrennt kompiliert und anschließend mit dem Catch2-Runner verbunden. In den Lehrertests keine eigene Catch2-main-Funktion definieren.

Funktionen testen

#include <catch2/catch_test_macros.hpp>
// C-Antworten benötigen C-Linkage; die Tests selbst sind immer C++.
#if __has_include("answer.c")
#define ANSWER_LINKAGE extern "C"
#else
#define ANSWER_LINKAGE
#endif
ANSWER_LINKAGE int calculate_sum(int, int);
TEST_CASE("sum") { REQUIRE(calculate_sum(2, 3) == 5); }

Bei C-Antworten müssen die getesteten Funktionen mit C-Linkage deklariert werden, zum Beispiel extern "C" int calculate_sum(int, int);. Das gezeigte Muster funktioniert mit beiden Antwortsprachen, ohne die Implementierung einzubinden.

Antwortsprache wechseln

Ein Wechsel zwischen C17 und C++17 schreibt Template und Tests nicht um. Prüfen Sie den Code und die Funktionsdeklarationen; unpassende Linkage kann einen undefined reference-Linkerfehler verursachen.

Die Beispiele verwenden ANSWER_LINKAGE vor jeder getesteten Funktionsdeklaration. Die Umgebung stellt answer.c für C und answer.cpp für C++ bereit. __has_include erkennt die C-Antwort, ohne sie einzubinden. __cplusplus eignet sich dafür nicht, da die Catch2-Tests immer C++ sind.

Eigene main-Funktion für Run

Run Code startet die main-Funktion der Studentenlösung und ruft keine Funktionen automatisch auf. UnitTests verwenden stattdessen die main-Funktion von Catch2. Beim Kompilieren für UnitTests ist LETTO_UNIT_TEST für Antwort und Tests definiert; bei run und compile ist es nicht definiert.

int calculate_sum(int a, int b) { return a + b; }

#ifndef LETTO_UNIT_TEST
#include <stdio.h>
int main(void) {
    printf("Sum: %d\n", calculate_sum(2, 3));
    return 0;
}
#endif

Die getesteten Funktionen bleiben außerhalb des Guards. Hilfsfunktionen und Includes, die nur main benötigt, können innerhalb stehen. Eine ungeschützte main-Funktion kollidiert beim Linken mit Catch2. Reine Funktionsantworten dürfen main weglassen.

Dataset variables (teacher tests)

Die Lehrertests erhalten eine pro Student erzeugte dataset.h mit den aktuellen Dataset-Werten. Die Werte stehen nur bei check und Bewertung bereit. Studentencode darf keine Dataset-Werte importieren; die Lehrertests geben sie als Funktionsargumente weiter. run und compile erhalten keine dataset.h.

helpers.h definiert variable mit float value und const char *unit fuer C und C++. Beide Header werden automatisch bereitgestellt. Download fuer die lokale Vorbereitung der Lehrertests: helpers.h (C und C++).

In beiden Sprachen gibt es eine Tabelle DATASET_VARIABLES und DATASET_VARIABLE_COUNT. dataset_get("name") liefert einen Zeiger auf variable oder NULL fuer einen fehlenden Namen. Diese Schnittstelle ist auch in den als C++ kompilierten Catch2-Tests verwendbar:

#include "dataset.h"
#include <catch2/catch_test_macros.hpp>
#if __has_include("answer.c")
#define ANSWER_LINKAGE extern "C"
#else
#define ANSWER_LINKAGE
#endif
ANSWER_LINKAGE float double_value(float);
TEST_CASE("dataset") {
    const variable *number = dataset_get("number");
    REQUIRE(number != nullptr);
    REQUIRE(double_value(number->value) == number->value * 2);
}

Einheit ueber number->unit lesen. Strings mit strcmp vergleichen. Dataset-Werte muessen numerisch sein und in den Wertebereich von float passen; eine fehlende Einheit ist ein leerer String. Ohne Dataset ist die Tabelle leer. Die Bewertung verwendet immer das aktuelle studentische Dataset, keine gespeicherten Vorschauwerte.

Files

Hochgeladene Dateien und Beispieldateien stehen beim Ausführen und Testen im Arbeitsverzeichnis bereit. Eine Datei auswählen, um sie herunterzuladen oder mit delete selected aus der Aufgabe zu entfernen. Das Entfernen löscht keine gespeicherten Inhalte, die andere Aufgaben verwenden.

CPU time limit (seconds)

Begrenzt die Prozessorzeit für Run, Check und Score (Standard: 5 Sekunden). Wartezeiten und Ein-/Ausgabe verbrauchen keine CPU-Zeit. Die angezeigte verstrichene Zeit misst die gesamte Anfrage und kann daher länger sein. Die Ausführungsumgebung beendet eine Ausführung zusätzlich nach etwa dem Doppelten des CPU-Limits als Schutz vor endlosem Warten. Bei 5 Sekunden CPU-Limit sind daher etwa 10 Sekunden zuzüglich Upload-, Warteschlangen- und Netzwerkzeit möglich.
